# คู่มือนำขึ้นออนไลน์

## เลือกทางไหน
| ทาง | เหมาะกับ | ข้อดี | ข้อจำกัด |
|---|---|---|---|
| **A. Streamlit Community Cloud** | สาธิต/ส่งงาน/ทดลองกับคนจำนวนน้อย | ฟรีหรือถูก ง่ายที่สุด ได้ https ให้เลย | ที่เก็บไฟล์ไม่ถาวร (ประวัติแชทและไฟล์ที่อัปโหลดผ่าน Admin หายเมื่อแอปรีสตาร์ท) หน่วยความจำจำกัด (ตามเอกสารของ Streamlit ขั้นต่ำ 690 MB สูงสุด 2.7 GB) จึงต้องใช้ `EMBEDDINGS=openai` และแอปจะหลับถ้าไม่มีคนเข้า 12 ชั่วโมง |
| **B. Docker บน Render / Railway / Fly.io** | ใช้งานจริงระยะยาว | ต่อดิสก์ถาวรได้ ข้อมูลไม่หาย | ต้องเลือกแพ็กเกจที่มีดิสก์ถาวร (ตรวจเงื่อนไขและราคาล่าสุดที่เว็บผู้ให้บริการ) |
| **C. เซิร์ฟเวอร์ของคุณเอง (VPS/มหาวิทยาลัย)** | ควบคุมเองทั้งหมด | ใช้โมเดลค้นหาในเครื่องได้ ไม่เสียค่า embedding | ต้องดูแลเอง และต้องตั้ง https เอง |

ถ้าเพิ่งเริ่ม แนะนำ **A เพื่อสาธิตก่อน** แล้วค่อยย้ายไป B เมื่อจะใช้จริง

---

## A. Streamlit Community Cloud
1. **เอาโค้ดขึ้น GitHub** (repo แบบ private ได้) โดยห้าม commit `.env` — ไฟล์ `.gitignore` กันไว้ให้แล้ว
   ```bash
   git init
   git add .
   git commit -m "waste rag chatbot"
   git branch -M main
   git remote add origin https://github.com/<ชื่อคุณ>/<ชื่อ repo>.git
   git push -u origin main
   ```
2. เข้า share.streamlit.io แล้วสร้างแอปใหม่ เลือก repo, branch `main`, Main file path = `app.py`
3. ใน Advanced settings เลือก Python (ค่าเริ่มต้น 3.12 ใช้ได้ หรือเลือก 3.11) และวางค่าในช่อง **Secrets** ตามไฟล์ `.streamlit/secrets.toml.example`
   (ต้องมี `EMBEDDINGS = "openai"` และ `OPENAI_API_KEY` เพราะแพ็กเกจฟรีรันโมเดลในเครื่องไม่ไหว)
4. กด Deploy รอติดตั้งไลบรารี แล้วเปิดลิงก์ที่ได้
5. ข้อมูลความรู้: แก้ไฟล์ใน `data/` และ `locations/points.csv` ที่เครื่อง แล้ว `git push` (อย่าพึ่งการอัปโหลดผ่าน Admin เพราะจะหายเมื่อรีสตาร์ท)

## B. Docker (Render / Railway / Fly.io หรือที่อื่นที่รับ Dockerfile)
1. ลองในเครื่องก่อน (ต้องติดตั้ง Docker)
   ```bash
   docker build -t waste-bot .
   docker run -p 8501:8501 --env-file .env -v waste-data:/data waste-bot
   ```
   เปิด http://localhost:8501 — `-v waste-data:/data` คือดิสก์ถาวร ประวัติแชทและข้อมูลที่แก้ผ่าน Admin จะอยู่ครบหลังรีสตาร์ท
2. บนผู้ให้บริการ: สร้าง service จาก repo (ใช้ Dockerfile) → ตั้งตัวแปรสภาพแวดล้อมตาม `.env.example` →
   **ต่อดิสก์ถาวรไปที่ `/data`** → ผู้ให้บริการส่วนใหญ่กำหนดพอร์ตผ่านตัวแปร `PORT` ซึ่ง Dockerfile รองรับแล้ว
3. ถ้าจะใช้โมเดลค้นหาในเครื่องแทน OpenAI: build ด้วย `--build-arg LOCAL_EMBEDDINGS=1` (ภาพใหญ่ ใช้ RAM อย่างน้อย 2 GB)
4. ครั้งแรกระบบคัดลอก `data/` และ `locations/` ไปไว้ที่ `/data` ให้เอง หลังจากนั้นข้อมูลบนดิสก์ถาวรคือของจริง
   การแก้ไฟล์ใน repo จะไม่ทับข้อมูลบนดิสก์ ให้แก้ผ่านหน้า Admin แทน

## C. เซิร์ฟเวอร์ของคุณเอง
ใช้ Docker ตามข้อ B หรือรัน `pip install -r requirements-local.txt` แล้ว `streamlit run app.py --server.port 8501`
วางหน้า reverse proxy ที่มี https (เช่น Caddy หรือ Nginx) ต้องเปิด WebSocket ให้ผ่านด้วย

## ตัวแปรสำคัญ (ดูครบที่ `.env.example`)
- `OPENAI_API_KEY` หรือ `ANTHROPIC_API_KEY` และ `LLM_PROVIDER`
- `EMBEDDINGS=openai` เมื่อไม่ได้ติดตั้งโมเดลในเครื่อง
- `ADMIN_PASSWORD` **ต้องตั้ง** ก่อนเปิดสาธารณะ
- `DAILY_QUESTION_LIMIT`, `DAILY_IMAGE_LIMIT`, `DAILY_GLOBAL_LIMIT` คุมค่าใช้จ่าย
- `APP_STORAGE` ที่เก็บถาวร (Docker ตั้งเป็น `/data` ให้แล้ว)

## เช็กลิสต์ก่อนเปิดให้คนทั่วไปใช้
- [ ] ตั้ง `ADMIN_PASSWORD` และเก็บคีย์ไว้ในช่อง Secrets/ตัวแปรของผู้ให้บริการเท่านั้น ไม่อยู่ใน GitHub
- [ ] ตั้งวงเงินรายเดือนในแดชบอร์ดของผู้ให้บริการ AI (OpenAI/Anthropic) กันค่าใช้จ่ายเกิน
- [ ] ปรับโควตาต่อวันให้เหมาะกับจำนวนผู้ใช้
- [ ] ตรวจข้อมูลจุดรับขยะ เวลาทำการ และกฎของพื้นที่กับหน่วยงานจริง
- [ ] เปิดผ่าน https (ปุ่มขอตำแหน่งในหน้า Map ใช้ไม่ได้บน http ธรรมดา)
- [ ] ผู้ใช้เห็นข้อความเรื่องข้อมูลส่วนบุคคลแล้ว (มีในแถบข้างและหน้าแรก) ตรวจว่าตรงกับนโยบายของหน่วยงาน
  และสอบถามผู้รับผิดชอบเรื่อง PDPA ถ้าจะเก็บประวัติผู้ใช้จริง (เอกสารนี้ไม่ใช่คำแนะนำทางกฎหมาย)
- [ ] รันชุดทดสอบที่หน้า Admin แท็บ "ชุดทดสอบ" ด้วยโหมด LLM อย่างน้อย 1 รอบ ข้อสำคัญต้องผ่านครบ
- [ ] PyMuPDF ใช้ใบอนุญาต AGPL ถ้าเปิดบริการสาธารณะ ให้ตรวจเงื่อนไข หรือถอดออกจาก `requirements.txt` (ระบบใช้ `pypdf` แทนได้)

## ปัญหาที่พบบ่อย
- **ติดตั้งไม่ผ่านบน Cloud / แอปดับเพราะหน่วยความจำ:** ตรวจว่าตั้ง `EMBEDDINGS=openai` และ `requirements.txt` ไม่มี torch
- **ข้อมูลหายหลังรีสตาร์ท:** ยังไม่ได้ต่อดิสก์ถาวร หรือใช้ทาง A
- **อัปโหลดไฟล์ใน Admin ได้ข้อผิดพลาด 403 หลัง reverse proxy:** ตรวจการตั้งค่า proxy ให้ส่ง header เดิมและเปิด WebSocket
- **ปุ่มตำแหน่งไม่ทำงาน:** ต้องเป็น https และผู้ใช้ต้องกดอนุญาตในเบราว์เซอร์
